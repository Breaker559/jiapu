# 家谱 Jiapu

家谱、亲属关系、照片与家族故事管理应用，支持 Windows 本地运行和 Docker 部署。当前版本 **0.1.0**。

## 现在怎么打开

**这台 Windows 电脑的依赖已配置，直接双击本目录中的 [启动家谱.cmd](启动家谱.cmd)。**

1. 等待窗口出现 `Jiapu is ready: http://127.0.0.1:8765`。
2. 启动成功后会自动打开浏览器；也可以点击 [打开家谱](http://127.0.0.1:8765)。
3. 已有账号直接登录；新用户点击“注册账号”创建独立家族空间。全新站点第一次使用先由站点所有者创建管理员。注册后请保存恢复码，没有预设账号或密码。

服务在后台运行，启动窗口显示成功后可以关闭，关闭浏览器也不会停止服务。电脑关机或重启后，重新双击启动文件即可。重复启动会打开已有服务，不会另外创建家族或清空资料。

| 操作 | 方法 |
| --- | --- |
| 启动并打开网页 | 双击 `启动家谱.cmd` |
| 进入家谱 | [http://127.0.0.1:8765](http://127.0.0.1:8765) |
| 浏览虚构示例 | [http://127.0.0.1:8765/?demo=1](http://127.0.0.1:8765/?demo=1) |
| 停止后台服务 | 双击 `停止家谱.cmd` |
| 查看启动错误 | 打开 `data/server-error.log` |
| 本地资料位置 | `data` 目录；停止或重启服务会保留资料 |

### 在 PowerShell 中启动

如果已经在项目目录打开 PowerShell，运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -OpenBrowser
```

从其他目录启动这台电脑上的项目，可运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\surfz\Desktop\新建文件夹\族谱\start.ps1" -OpenBrowser
```

本地运行使用 Python 3.12 和 Node.js 22，首次安装依赖、首次构建需要联网。当前电脑已安装好，无需先安装 Docker。

### 网页打不开时

先双击 `启动家谱.cmd`，等服务就绪，再访问上面的 HTTP 地址。`127.0.0.1` 指当前这台电脑；手机或其他电脑访问请使用下方 Docker / 局域网部署说明。

在项目目录运行以下命令检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8765/api/health
```

- 返回 `ok: True`：服务已启动；打开 [家谱](http://127.0.0.1:8765)，必要时按 `Ctrl + F5` 刷新网页。
- 提示连接被拒绝：后台服务未运行，重新执行启动文件；启动失败时查看窗口错误和 `data/server-error.log`。
- 提示 `8765` 被占用：可运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Port 8766 -OpenBrowser`，然后访问 `http://127.0.0.1:8766`。
- 修改代码后页面仍是旧版本：先停止服务，再运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Rebuild -OpenBrowser`。

## Docker 快速运行

在已安装 Docker 的主机上，从项目目录执行：

```sh
docker compose -f compose.sqlite.yaml up -d --build --wait
```

然后访问该主机上的 [http://127.0.0.1:8765](http://127.0.0.1:8765)。数据库与照片保存在 Docker 数据卷中。其他设备访问需要配置监听地址和服务器 IP，详见 [Docker 部署说明](docs/DOCKER.md)。

## 多账户、注册与密码

- 登录页提供“登录 / 注册账号”。注册时填写称呼、邮箱、家族名称和密码，完成后自动登录，并创建自己的空家族空间。
- 每个账号独立登录；每个家族的资料按成员权限隔离。普通注册用户只拥有自己家族的管理权，不是站点管理员，也不会自动加入原有家族。
- 加入亲友的家族：让所有者在“家族设置”生成邀请码，在登录页选择“我有家族邀请码”。已有账号用原邮箱和密码加入即可，同一账号可切换多个家族。
- 账号操作统一在右上角头像菜单：查看当前账号，选择“修改密码”或“退出登录”。点击头像只展开菜单，不会直接退出。
- 修改密码：右上角头像 → 修改密码，输入当前密码和新密码。当前页面保持登录，其他设备的旧会话失效；请保存新显示的恢复码。
- 忘记密码：登录页点击“忘记密码”，用邮箱和保存的恢复码重设。当前未接入邮件验证或邮件找回；恢复码也丢失时，需要由服务器维护者在本机协助重置。
- 开放注册默认开启，可在“站点管理”中即时开关。Docker 的 `.env` 中设置 `QINPU_ALLOW_REGISTRATION=0` 并重新 `docker compose ... up -d` 可从部署层关闭公开注册，保留邀请加入；本地运行可先在 PowerShell 设置 `$env:QINPU_ALLOW_REGISTRATION='0'` 再启动服务。
- 对外访问使用 [Docker 部署说明](docs/DOCKER.md) 配置域名、HTTPS 和访问地址。仅有本机 `127.0.0.1` 地址时，其他设备不能通过此地址访问。

左下角“使用帮助”提供图谱框选与排版、邀请家人、备份恢复和账号操作说明，并可跳转到图谱或家族设置。手机上先打开左上角导航，即可找到帮助入口。

## 站点管理后台

用首次初始化时创建的站点管理员登录，点击左侧“站点管理”，或打开 [站点管理后台](http://127.0.0.1:8765/#admin)。即使管理员没有加入任何家族，也可以进入后台。

- 查看全站账号数、站点管理员数、家族空间数和近 7 天注册数。
- 按姓名、邮箱搜索，按站点角色筛选，分页浏览账号；账号详情展示所属家族及各家族中的角色。
- 查看注册时间和最近登录时间，统一按北京时间显示。更新前的历史账号没有记录过的时间显示为“未记录”，以后登录时更新最近登录时间。
- 开放或关闭公开注册，设置即时生效并保存到数据库，重启后保留。关闭后已有账号仍可登录，也仍可通过家族邀请加入。`QINPU_ALLOW_REGISTRATION=0` 优先级更高，后台不能覆盖部署层的关闭设置。

“站点管理员”与“家族所有者”是不同权限：普通注册用户管理自己的家族，但不能访问全站账号目录。站点后台展示账号和家族成员身份；家族人物、照片、故事仍按该家族的成员权限访问。后台不提供查看密码、删除账号或提升站点权限功能。

## 文章与记忆收藏夹

- “家族档案 → 记录故事”默认使用 Markdown，支持标题、加粗、列表、引用、链接和表格；可切换编辑/预览，也可导入 `.md` 文件（正文最多 30,000 字符）。旧档案保留纯文本显示，可在编辑器中切换格式。
- 在正文中放好光标，点击“上传图片 / 视频”直接插入，或从已有家族媒体中选择后“插入正文”。媒体同时保存在相册的“文章附件”中，沿用家族成员访问权限；仅编辑可见的媒体不能插入家族公开范围的文章。
- 阅读文章时可“导出 .md”。源文件通过 `![说明](media:媒体编号)` 引用当前家族媒体，不包含媒体二进制；跨站迁移请使用“备份与迁移”的完整加密家族包，恢复时会一并还原媒体和文章引用。
- 首页“记忆收藏夹”和“家族相册”均支持图片、视频混合上传，视频显示播放标记和时长，点击后可播放和拖动进度。图片可设为头像、封面；视频用于收藏和文章播放。
- 图片支持 JPEG、PNG、WebP；视频支持 **MP4（H.264，音频 AAC/MP3）** 或 **WebM（VP8/VP9/AV1，音频 Opus/Vorbis）**。服务端生成视频封面并保留原文件，不自动转码；不支持的编码会提示先转换再上传。
- Markdown 不执行原始 HTML，也不直接加载外站图片；请先上传图片到家族媒体库。家族书打印保留文章图片，视频位置显示在线播放提示。

## 复杂家庭与图谱

- 图谱页铺满窗口剩余高度，标题与工具栏保持紧凑。默认以便于阅读的比例打开，可拖动、缩放或点击“查看全图”总览；“显示设置”中调整称谓和房支，右上方“查关系”打开两人关系查询。
- 每条父母到子女的关系分别录入，支持单亲、不同子女有不同父母、收养与继亲并存。不会因为两人共同育儿而自动生成婚姻、伴侣或亲生关系。
- 配偶、非婚伴侣、前配偶、前伴侣、共同育儿分别标注。其他关系用备注描述；可以标为待核实，并保留来源和关系时间的文字记载。
- 默认“家庭树”按相同的父母组合汇总亲子分支，不同组合分别连接；分支显示“子”“女”等称谓，不用关系性质代替人物称谓。点击主干可查看全部原始关系。需要逐条核对时切换“关系明细”；“显示称谓”默认开启，可随时关闭。所有者和编辑可修改关系，人物档案里也有编辑入口。
- 图谱按每户家庭展开：父母在上，共同连接本组孩子；孩子分支显示子、女称谓，父母卡片下方不重复标注父、母。同一人物可以在上一户是子/女，在下一户又是父/母。婚姻连线按这户家庭所属分支显示有方向的夫/妻、前夫/前妻；没有可区分的分支时沿用已保存的关系方向。不会因切换房支过滤而改变已确定的方向。
- 世次只在图谱最左侧按层显示，随画布纵向移动与缩放对齐。没有世次记载时显示“第 N 层”，同层记载冲突时提示“世次待核对”，不改写人物原始资料。拖动人物不改变其所属层级。
- 人物卡片明确显示男/女/性别未注明。在世人物显示完整生日和当前周岁；已故人物显示生卒日期与享年。出生日期按原始历法展示，农历在可换算时按阳历计算周岁；日期不完整或近似时标为估算或待考。当前日期按上海时区更新，页面停留跨天或恢复可见时也更新年龄；2 月 29 日出生者在非闰年 3 月 1 日增加周岁。
- 悬停人物打开“概览、影像、生平”资料浮层，可切换标签、查看亲属关系或进入完整档案；手机和键盘可用卡片右侧的预览按钮。浮层只使用当前账号可见的人物、图片和视频。
- 排版工具栏支持框选、整组拖动、六种对齐和水平/垂直等距分布。选中人物后显示浮动对齐工具，不会挤压或移动画布；移动模式下按住 Shift 拖动可临时框选，Ctrl / ⌘ 点选增减人物；框选模式下按住空格拖动画布。对齐至少选择 2 人，等距分布至少选择 3 人。
- 吸附默认开启，拖动时对齐其他人物的边缘或中心，并显示参考线；可随时关闭。点击“一键排版”按亲属关系整理当前可见人物并查看全图。拖动、对齐、分布和自动排版均支持撤销/重做（Ctrl / ⌘ Z、Ctrl / ⌘ Shift Z），最多保留本次会话最近 30 步。
- 手动布局按家族及筛选范围自动保存在当前浏览器，刷新与切换页面后保留；不会同步到其他设备或进入家族备份。图谱获得焦点时 Ctrl / ⌘ A 全选，Esc 取消选择。手机可拖动画布与双指缩放，左下角按钮查看全图。“子”“女”等称谓显示在子女连线侧边，自定义长称谓也从线旁展开。
- 旧版 `spouse` 记录仍保留原始含义，显示为“配偶 / 伴侣（旧记录，待细分）”，由编辑核实后选择具体类型。没有批量改写已有家族关系。
- 首页预览只展示一位家人与其已记录的子女，避免将其孩子误认为另一人的共同子女。示例人物与关系全部为虚构。

## 统一称谓设置

进入“家族设置 → 称谓设置”，把“子的称谓”填为“儿子”，点击“保存并统一应用”，本家族图谱、人物档案、关系查询和首页预览中的对应称谓会一起更新。可以一次修改多项；已有关系和以后新增的关系都沿用设置，不需要逐条修改人物。

也可在图谱上方点击“修改称谓”，或点击图上的称谓/连线，在关系详情中选择“修改称谓”。保存后返回原图谱或关系详情，无需离开当前页面。关系详情另有“编辑关系”，并显示双方已记录的性别；点击人物可进入档案核对和修改资料。

- 双人关系详情和录入选项显示“夫妻”“曾为夫妻”等关系类别；图谱按每户家庭显示夫/妻、前夫/前妻等有方向的个人称谓。两类叫法分别在“双人关系名称”和“人物称谓”中统一设置。妻子只有在已录入对应亲子关系时，才同时显示为这一组孩子的母亲。
- 人物称谓默认使用父、母、子、女、夫、妻；“使用日常称呼”可一次填入父亲、母亲、儿子、女儿、丈夫、妻子。“恢复默认简写”和预设都需保存后生效。
- 统一设置共 31 项；“更多称谓”支持收养、继亲、前配偶、伴侣、共同育儿及性别未注明时的叫法。未单独设置的派生称谓跟随基础称谓，例如子改为儿子时，养子随之显示为养儿子；单独填写养子的称谓可指定独立叫法。
- 称谓根据已记录的性别和关系方向生成，不从姓名猜测性别。父亲查看男性孩子显示子，孩子查看父亲显示父。关系性质在编辑与详情中单独保留；新建父母关系默认未注明性质。
- 只有家族所有者可统一保存；多个家族互不影响。只读示例允许预览，不保存。设置保存在服务器，刷新后保留，也随加密家族包迁移；其他已打开的浏览器在刷新或重新获取家族资料后使用新设置。
- 每项自定义称谓最多 12 个字符，留空使用默认或跟随基础称谓。保存采用版本校验，避免覆盖其他会话刚保存的设置。

## 日期规则

- 人物档案、成员卡片和图谱预览按录入历法展示生日：农历生日突出农历，阳历生日突出阳历，另一历法作为下方小字备注。生日提醒按该人物选择的纪念历法展示下一次日期。

- 精确双历换算范围：公历 **1900-01-31 至 2099-12-31**。范围外保留原始记载，显示未换算。
- 出生年未知时可记录月日；只有年份时不补造月日。没有足够信息时，不跨历法推算生日。
- 每个人选择按原始历法、阳历或农历纪念；闰月和当年缺失日期另行设置。
- “日期原文”保存口述或原谱记载；不准确日期可标注约数。
- 当前生日页提供下一次生日的查阅，没有自动邮件、短信或系统推送。
- 日期按年月日保存，纪念日按 `Asia/Shanghai` 计算，不因浏览器时区改变生日。

## 数据在哪里

- `data/qinpu.db`：本地 SQLite 数据库。
- `data/media`：每个家族的图片、视频原文件与网页缩略图；没有公开静态文件入口。
- `data/server*.log`：本地运行日志。
- 人物、关系和照片不写在浏览器 localStorage；浏览器保存显示偏好、图谱布局位置和上次打开的家族编号。
- 人物字段的来源与隐私、图片的说明和关联、修订历史随家族备份迁移。

家族迁移包采用 AES-256-GCM 加密，scrypt 派生密钥。请保存备份密码；应用不能找回它。恢复创建一个新的家族并重映射对象编号，不覆盖已有家族；登录账号、邀请、会话与服务器密钥不迁入。旧家族与恢复副本之后分别修改会产生分叉，此版没有双向同步。

整个本地实例灾备：先停止服务，再完整复制 `data` 目录到另一块磁盘；不要只在运行期间复制 `qinpu.db` 一个文件而忽略 WAL。恢复整个目录会连同账号一起恢复，应按私密备份保管。

## 开发运行

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm ci
npm run build
.\.venv\Scripts\python.exe -m uvicorn server.app:app --host 127.0.0.1 --port 8765
```

开发前端可单独运行 `npm run dev`，Vite 将 `/api` 转发到 8765。生产构建由 FastAPI 同源提供，页面与日期换算不依赖在线 CDN。

`start.ps1 -Rebuild` 会重新安装前端锁定依赖并构建。后端依赖更新（包括本次新增的视频处理 PyAV）时，先运行 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`。代码变更后需重启后端。升级前停止服务并备份数据；当前数据库版本为 1，后续改变表结构时需编写正式迁移，不可直接假定旧库可用。

## Docker 部署

安装 Docker Engine / Docker Desktop（Linux 容器）和 Compose v2.20 或更高版本。在项目目录运行以下命令，无需在宿主机安装 Python、Node.js 或数据库：

```sh
docker compose -f compose.sqlite.yaml up -d --build --wait
```

打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)，创建管理员即可使用。默认项目名为 `jiapu`，SQLite 数据库和照片保存在命名卷 `jiapu_family_data`，重建容器与普通 `down` 后仍保留。首次启动为独立空实例，不会自动导入这台电脑的 `data` 目录；可在原应用导出加密家族包，再从容器应用中导入。

NAS / 局域网访问：复制 `.env.example` 为 `.env`，设置 `QINPU_BIND_ADDRESS=0.0.0.0`，将服务器 IP 加入 `QINPU_ALLOWED_HOSTS`，将完整访问地址加入 `QINPU_ORIGINS`，再运行启动命令。例如服务器为 `192.168.1.20`，填写 `QINPU_ALLOWED_HOSTS=192.168.1.20` 和 `QINPU_ORIGINS=http://192.168.1.20:8765`，即可通过该地址访问。`QINPU_PORT` 可修改对外端口。

已有 PostgreSQL 用户可继续使用 `compose.yaml`：在 `.env` 中设置随机 `QINPU_DB_PASSWORD` 后运行 `docker compose up -d --build --wait`。新的默认项目名为 `jiapu-postgres`；升级已有部署时，必须沿用原项目名（`docker compose -p 原项目名 ...`），以连接原数据库和照片卷。

完整的 HTTPS 反向代理、PostgreSQL 配置、备份恢复、升级和验收命令见 [Docker 部署说明](docs/DOCKER.md)。当前开发机没有 Docker 引擎，容器构建、重启持久化及 PostgreSQL 运行仍需在 Docker 主机执行文档中的验收；本地应用测试不能替代容器实测。

应用显示名称已统一为“家谱 / JIAPU”。已有环境变量 `QINPU_*`、数据库文件 `qinpu.db`、登录会话及 `.qinpu` 加密包标识继续兼容，避免改名造成资料或登录状态丢失。
